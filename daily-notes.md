# Daily notes (written by Muse)

One note per day. The workflow appends today's note to daily-log.md once, then adds a short heartbeat line per run.

2026-11-27: Start small, ship daily. A tiny commit beats a perfect plan that never leaves your notes.
2026-11-28: Read the error message twice before Googling it. Half of all bugs confess in the first two lines.
2026-11-29: Name things for the next person reading your code at 2am — that person is usually future you.
2026-11-30: If a function needs a comment to explain WHAT it does, rewrite the function. Comments are for WHY.
2026-12-01: Version control is a time machine. Commit when it works, not when it's perfect.
2026-12-02: The fastest code is the code that never runs. Delete before you optimize.
2026-12-03: Debug by reproducing first. If you can't reproduce it, you can't prove you fixed it.
2026-12-04: A test that never fails is a test that never tests anything. Make it fail once, on purpose.
2026-12-05: Keep functions small enough to hold in your head. If you can't, split it.
2026-12-06: Read other people's code. Most of what you learn as a dev comes from reading, not writing.
2026-12-07: Don't repeat yourself, but don't abstract too early either. Three copies is the signal to extract.
2026-12-08: The best debugging tool is a rubber duck. Explain the bug out loud and the fix often appears.
2026-12-09: Ship the boring solution first. Clever code is a debt you pay every time you revisit it.
2026-12-10: Learn the keyboard shortcuts of your editor. The minutes compound into hours.
2026-12-11: A bug you can't explain is a bug that will return. Understand the root cause, not just the symptom.
2026-12-12: Write the README before the code. If you can't explain it simply, you don't understand it yet.
2026-12-13: Back up before you refactor. A safety net makes you braver, and braver means faster.
2026-12-14: Code review is not about catching mistakes — it's about sharing context. Be kind, be specific.
2026-12-15: The hardest part of a feature is not building it, it's deciding what NOT to build.
2026-12-16: Use the terminal. GUIs hide what the machine is actually doing; the terminal shows it.
2026-12-17: A slow query is usually a missing index, not a slow database. Check EXPLAIN before blaming the server.
2026-12-18: Commit messages are documentation. Write them for the person who will bisect this in six months.
2026-12-19: Take a break when you're stuck. The solution often arrives in the shower, not at the keyboard.
2026-12-20: Don't build for scale you don't have. One user, then ten, then a thousand — in that order.
2026-12-21: Learn one new thing about your stack every day. Compound knowledge beats weekend cramming.
2026-12-22: If it works on your machine but not on the server, the difference IS the bug. Compare environments.
2026-12-23: Delete dead code. Every unused function is a lie your codebase tells its readers.
2026-12-24: Automate the boring parts. If you do it twice, script it; if you do it ten times, you already should have.
